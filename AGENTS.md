# Agent Notes for Cranamp

- EQ artwork: use the GUI EQ workbench or `studio_eq`. All eleven sliders share 28 level frames and two handle cells; frames are levels, not unique bands. For visible handles, match track, handle and adjacent background colors exactly, then inspect all shared destinations at mixed levels. Never leave inserted-looking matte rectangles. The explicit artwork-only mode exports the Björk-style 275×163 EQMAIN.BMP omission while preserving full project sources; it removes graphics, not hit targets. Read docs/skin-studio/equalizer-workbench.md.

- A passing stroke report does not approve the composition. Compare the user's marked boundaries with the actual GPU image: never replace a connected illustration with independently cropped panels, procedural rectangle fills or kitten stickers. Inspect the full illustrated subjects and the transition into runtime fills. VISCOLOR slot 0 is an opaque RGB fill; magenta is ordinary ink. REGION.TXT provides whole-window cutouts. For a palette-only playlist, paint its adjacent header/footer into the exact fill color instead of leaving a ruler-straight artwork splice. Preserve the annotated baseline and review every marked region before calling it fixed.

- Author continuous artwork once in joined-canvas coordinates. Never restart a stroke, texture phase, crop scale or pattern period at a component edge. Derive target lists from coverage rather than a handwritten list that can omit overlays such as `equalizer.preamp.line`. Use Auto/all states for actual crossings; when a shared sprite cannot store unique local artwork, design an opaque repeating track that stays consistent throughout its travel. Review every `continuity` result, including native samples and `covering_sources`; use `require_continuity:true` for strokes that must remain visible across joins. Clipped, overwritten or hidden ink is not success just because source writes succeeded. Intentional moving-sprite occlusion must be inspected explicitly. Inspect the exterior halo and GPU in all states; repeated rails must meet header/footer at every resize phase.

- Classic Winamp BMP sprites are opaque rectangular copies, including #ff00ff. Never treat magenta as a sprite hole. Alpha zero erases only the active paint layer; missing stamp characters skip paint. Match moving silhouettes to an intentional track cross-section and inspect all states and positions. Use studio_regions to generate REGION.TXT from an explicit window mask: it clips the entire window, never just a sprite. Studio emits merged rectangles for Audacious compatibility. Review transparency.incomplete_moving_sprites and studio_validate.exportable. Passing format checks does not certify cross-player visual identity. Follow docs/skin-studio/classic-compatibility.md; older key-transparency recipes are obsolete.

- Start a skin boundary inspection with `studio_study {rect:[x,y,w,h],states:true}`: it returns native and enlarged four-state editor crops with four pixels of context and source/runtime coverage in one read-only call. Inspect overlapping control cells as well as the background. The GUI Pixel Study follows the live composition; clipboard pixels are separate. Use the actual GPU preview before approving the artwork.

- Before declaring any Skin Studio region inaccessible or leaving a blank for runtime content, run `studio_probe {path:".../pixel-probe.json"}` on the whole joined canvas, then inspect the exact native rectangle with `studio_coverage` or `studio_pixel` and review its source targets. The probe exercises every pixel with the real writer in all four active/pressed views and all source variants without touching the live document. Runtime footprints are overlays, not exclusion masks: surrounding and underlying bitmap pixels may be painted. Distinguish actual palette-only playlist fill from editable backgrounds, control cells and footer margins; verify the result in the GPU player and alternate states.

- Review every `flat_drawable_areas` warning from draw, study and export, including its exact `largest_flat_square`. Do not reserve broad blank rectangles for readouts or sliders, request holes in source artwork, or mistake portability checks for visual approval. Put readable live content over continuous artwork, and complete all overlapping/shared sprite cells so they cannot reinstate an empty backdrop. Intentional negative space needs visual justification, never a claim that mapped bitmap pixels are inaccessible.

- For annotated skin corrections, preserve the annotated project and map every marked area to an explicit native rectangle before painting. Use `tools/skin-studio/region_review.mjs` with a region manifest to capture before/after editor crops, a 4-pixel exterior halo, ownership, and all four GPU states. Visually inspect every crop and complete overlapping sprites (including menu buttons, MONO/STEREO and repeated rails), not just the full canvas. Mapping counts and passing tests are not visual approval. Do not call a boundary fixed while another sprite still reinstates its old rectangular background.

- Keep all tests, test helpers, and fixtures in the root `/test/` directory. Never write test bodies, `#[test]` functions, inline test modules, or test-only helpers in implementation files, including `src/`, `tools/`, and `scripts/`. This rule applies to every language and to new generated code. Rust unit tests may retain a `#[cfg(test)]` and `#[path = ".../test/..."]` external module declaration beside the implementation to access private items. Register integration test targets in `Cargo.toml`; put web and platform tests under `/test/` too.

- Do every refactoring, code search, code analysis and code edit through the RustRover MCP (`mcp__rustrover__*`), never with grep, sed, Python heredoc scripts or hand edits for those jobs: `rename_refactoring` for renames, `apply_patch` and `create_new_file` for edits, `search_symbol`, `get_symbol_info` and `analyze_calls` for declarations, usages and call graphs (the IDE knows the code; a regex over its text does not, so `search_text` and `search_regex` are for strings and comments only), `get_file_problems`, `lint_files` and `run_inspection_kts` for analysis, `reformat_file` for formatting; for text searches run `scripts/dev/ide_search.py text|regex|symbol|file <query> [--in <glob>]... [--context N]` from the project root, which asks the same IDE server and prints each hit as path, line and matched text. Pass `projectPath` on every call; when the tools are missing, open the tree in RustRover first (`open -a RustRover <path>`), and say so before any fallback. Bash is for building, testing and git.
